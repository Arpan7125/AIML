Hyperparameter Tuning: max_depth¶

In [6]:
# Test different max_depth values
depth_range = range(1, 21)
train_scores = []
test_scores = []
cv_scores = []

for depth in depth_range:
    model = DecisionTreeClassifier(max_depth=depth, random_state=42)
    model.fit(X_train, y_train)
    train_scores.append(accuracy_score(y_train, model.predict(X_train)))
    test_scores.append(accuracy_score(y_test, model.predict(X_test)))
    cv_scores.append(cross_val_score(model, X_train, y_train, cv=5).mean())

# Find best depth
best_depth = depth_range[np.argmax(test_scores)]
print(f"Best max_depth (test accuracy): {best_depth}")
print(f"Best test accuracy: {max(test_scores):.4f}")
print(f"CV accuracy at best depth: {cv_scores[np.argmax(test_scores)]:.4f}")

Best max_depth (test accuracy): 3
Best test accuracy: 0.9386
CV accuracy at best depth: 0.9253

Summary of Key Observations¶

  1. Default trees overfit badly — they grow until every leaf is pure, basically memorizing training data.

  2. max_depth is the main knob — optimal depth is usually small (3-5 for these datasets). Deeper = more overfitting.

  3. min_samples_split / min_samples_leaf add more regularization by stopping splits on tiny subsets.

  4. Feature importance shows what actually matters (e.g., 'worst radius' for cancer diagnosis).

  5. Trees make step-wise predictions — you can see the staircase pattern in regression plots.

  6. Cross-validation matters — single train-test split can be misleading for hyperparameter tuning.

  7. Trees are interpretable — you can literally draw the whole decision path with plot_tree or export_text.

  8. No feature scaling needed — trees split on thresholds, not distances.

  9. Class imbalance handled naturally — can use class_weight='balanced' or balanced subsampling.

  10. Ensembles (Random Forest, Gradient Boosting) build on trees to reduce variance — that's next lab.
